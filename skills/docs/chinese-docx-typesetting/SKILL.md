# 中文 .docx 生成与分页工程

适用于任何「要交出去的中文 Word 文档」：简历、报告、方案、公文、杂志稿。核心不是排版好不好看，而是**一页塞不塞得下、打开会不会乱、改一句能不能一键重出**。

## 1. 一份内容源，N 个版本（不要手写多份）

反面做法：为每个方向单独改一份 docx —— 三份之后事实就开始互相漂移，第五个方向要重做一遍。

正确结构（本机已有可用实现，见 `references/resume-multi-direction.md` 末尾的路径）：

```
content.py   # 事实底座：学历/经历/数字/技能，全量只写一次
resume_gen.py# 渲染器：读 spec → 出 docx
SPECS = { "方向A": {...}, "方向B": {...} }   # 每个方向只声明 定位句/概述/能力/条目顺序
```

**事实（时间、机构、数字）在 content.py 里只有一份；方向之间只允许改：定位句、概述、能力标签、每条 bullet 的措辞与排序、板块先后。** 数字永远来自事实底座，不在方向 spec 里重打一遍 —— 否则下一版一定会出现 80 亿写成 80 万元这类事故。

跑法：
```bash
python3 content.py   # 出全部方向的 docx（需要 python-docx）
```

**改 content.py 不要盲写替换串。** 用 `execute_code` 做 `assert a in s; s = s.replace(a, b, 1)` 时，长中文字符串极易因换行位置、缩进、全角标点不一致而 AssertionError。先 `read_file` 把目标段落读回来，用读到的**原文**当 old_string；多处替换逐条 assert，失败信息里带上 `a[:60]` —— 一眼能分辨是上下文串错了还是文件已经变了。改完立刻跑一次生成 + 量页，不要攒着。

**替换整章时用切片，不要用 replace。** 拿本章标题当首锚点、下一章标题当尾锚点：
```python
a = s.index("## 五、家办与家族信托"); b = s.index("## 六、新加坡家办")
s = s[:a] + new_chapter + "\n" + s[b:]
```
这样是**原位换章，后面十几处的章号与「见本稿第七节」一个都不用动**——新增一章真正贵的成本不是写正文，是把交叉引用全改对。

**一次改动的数量超过五处，就写成一个脚本一次跑完**：逐条 `assert s.count(old) == 1`，命中数不对立即 `sys.exit(1)` 并打印标签，全部通过再统一重生成。不要用十个 patch 分十轮打——中途任何一轮失配都会留下一个改了一半的文件，而你已经记不清哪几处进了。动稿前先备份：`cp 方案正文.md 方案正文.md.bak.<日期>`，脚本里也加一句「备份不存在才备份」，重复跑不会把好稿覆盖成坏稿。

## 2. python-docx 中文排版：必须手写的几处

- **CJK 字体必须设 eastAsia**。只改 `run.font.name` 只影响拉丁字形，中文在 Word 里仍走主题字体（常见后果：正文变宋体、标题变等线，或者在别的机器上整体变样）。每个 run 都要：
  ```python
  rPr = run._element.get_or_add_rPr()
  rFonts = rPr.find(qn('w:rFonts')) or OxmlElement('w:rFonts'); rPr.append(rFonts)
  rFonts.set(qn('w:eastAsia'), '微软雅黑')
  ```
  同时把拉丁字体设为 Arial/Segoe 一类，中英混排才不别扭。
- **`w:pBdr` 必须排在 `w:spacing`/`w:ind`/`w:jc` 之前。** pPr 的子元素顺序由 schema 强制：画分隔线时先 `pPr.append(pBdr)`，再写 spacing，最后设 `p.alignment`（python-docx 会按 schema 把 `w:jc` 插到后面）。顺序错了 Word 报文档损坏。
- **`add_break` 不要链式调用**：`set_run(...).add_break(...)` 里 `set_run` 返回 None，直接报错。先 `r = p.add_run()`，再 `set_run(r, name, size)`，再 `r.add_break(WD_BREAK.LINE)`。
- **改别人 docx 里的文字要按段合并 runs。** 一句话在 `document.xml` 里被切成多个 `<w:r>`，直接做 XML 字符串 replace 会全部落空。做法：`"".join(r.text for r in p.runs)` → 替换 → 写回 `p.runs[0].text`、其余 run 清空（保住首 run 的格式）。**表格里的段落不在 `doc.paragraphs` 里**，要单独遍历 `cell.paragraphs`，否则表内文字漏改；改完另存新文件、原稿留底，方便逐项对照。
- **右侧日期用右对齐制表位，不要用空格凑**。制表位位置 = 页宽 − 左右页边距（A4 页边距 15mm 时是 180mm）。用空格在 Word 里必然错位。
- **章节标题的下分隔线用 `w:pBdr/bottom`**（single, sz=8, 深藏青），不要用下划线字符或一长串 `——`。
- **条目符号不要用 `List Bullet` 样式**。它挂在主题的列表定义上，中文字号和行距会被悄悄改掉；用悬挂缩进（left=5.2mm, first=-5.2mm）+ 手写 `• ` 前缀。
- 行距用 `WD_LINE_SPACING.MULTIPLE`，同时给每个段落显式 `space_before/space_after`（单位 Pt，可为小数如 0.5）。默认样式在 Word 与 LibreOffice 下不一致。

## 3. 分页控制：渲染 → 量像素 → 再删

**不要靠肉眼判断一页塞不塞得下，也不要靠 PDF 页数（溢出 3 行和溢出 30 行都显示「2 页」）。量内容底部到页面底边的余量。**

```bash
soffice --headless --convert-to pdf --outdir out out/*.docx
python3 scripts/docx_page_probe.py out --bottom-margin 13     # 每页内容底部 mm + 余量
```

判读标准（A4=297mm）：
- 余量 **< 10mm** → 危险，Word 换行与 LibreOffice 不同，很可能在对方电脑上溢出到第二页。
- 余量 **15–30mm** → 单页目标下的健康区间。
- 余量 **> 40mm** → 内容太薄，加内容而不是加大行距；留白 4cm 的简历像半成品。

**只差 15–25mm 就溢出的，删 3–5 行，不要动全局字号。** 更不要在「第二页只占 15%」时接受两页 —— 一页密一点永远比两页空一半好看。

### 表格：列宽配比与单元格行距是附件页数的主因

带附件的稿件里，**页数由表决定，不由字数决定**，纯文字量的估算在这里会完全失效。

- **列宽按内容配比，绝不等宽。** 等宽列是附件页数爆炸的头号原因：序号列和十几个字的名称列一样宽，15 行的表能撑到 7 页。列宽合计必须**正好等于版心宽度**：`twips = round(cm × 566.93)`；A4 + 上下 3.7/3.5cm、左右 2.8/2.6cm 时版心 15.6cm = **8845 twips**。一个已验证的五列配比（序号/名称/面向对象/时长/类别）= 480 / 3400 / 2400 / 1000 / 1565。
- **表字号降一档 + 单元格行距写死。** 表格内文字用五号（`w:sz=21`），并在**每个单元格**显式写 `<w:spacing w:line="300" w:lineRule="exact"/>` 与 `<w:trHeight w:hRule="atLeast"/>`。不写时单元格会继承正文的固定值 28 磅行高——同一张 15 行表，写了占 2 页，不写占 3 页。
- 固定布局要三处一致：`<w:tblLayout w:type="fixed"/>` + `<w:tblGrid>` 的 `gridCol` + 每个 `<w:tcW w:type="dxa">`；冲突时以 `tblGrid` 为准。列宽改完要 `[gc.get(qn('w:w')) for gc in tbl.find(qn('w:tblGrid'))]` 把实际值 dump 出来对合计，**数字比看图判断「这一列偶尔折没折行」可靠**。

省行数的高性价比位置，按顺序试：
1. 目的性最弱的那段早期经历整条删掉（技术方向可以删 5 年前的入门岗）。
2. 概述砍掉一层修饰，压掉 1 行。
3. 同类能力标签合并（「技术栈」和「资质」里重复出现的东西只留一处）。
4. 最后才是行距：加一个 COMPACT 排版档（行距 1.06 vs 1.12、上边距 13 vs 15mm、章节前距 6 vs 9pt）通常净赚 ~20mm，且不需要改任何内容。

### 架构图／流程图：别用 ASCII 方框字符画

`┌ ─ ┬ ┐ │ └ ┘` 这类制表符在 md 源码里靠等宽对齐，进 Word 后字体一换（等宽字体缺失时回落 Noto CJK）列就歪；十几行的框线图还必然被页底切断——上半页一截、下半页一截，客户看到的直接是废稿。这类图不要「画完再想办法调」，一开始就别画。

改用**紧凑树形**，压在 10 行内，只用 `├─ └─ │ →` 这几个字符，每行以「层级 ── 职责」收尾：

```
家族信托（持牌受托人）── 所有权层：持有、隔离、分配
├─ 100% 持股 → 基金载体 ── 装资产、享税务豁免
├─ 100% 持股 → 家办公司 ── 投资决策、风险管理、合规
└─ 100% 持股 → 隔离 SPV ── 仅承接质押物
```

判断标准：**超过 12 行、或需要三列以上横向并列，就不要画图，改写成分栏表格**（层级／装什么／不装什么／关键约束）。一页放不下的图等于没有图；表格反而能被逐格引用。

## 4. 两个必踩的坑

- **LibreOffice 会替换缺失的中文字体**（微软雅黑 → Noto Sans CJK），所以本机出的 PDF 只算「版面证明」，**不等于用户在 Word 里看到的样子**。单页目标留 ≥15mm 余量，并在交付时明说：投递件请用 Word 另存为 PDF。
- **字重和强调色不要靠渲染图判断。** 90dpi 的 `pdftoppm` 图上看不出加粗，视觉复核会报「这四条标题没加粗」而实际是对的。要判字重直接 dump run 属性：`[(r.text[:12], r.bold, str(r.font.color.rgb)) for r in p.runs]`。看图只看版面（有无方框、错位、截断、列挤），属性看 XML。
- **PDF 页数正确 ≠ 排版正确**。乱码方框、日期错位、文字截断在页数上完全看不出来。出稿前对渲染图做一次看图核对（姓名行/日期右对齐/有无方框/有无截断），量像素和看图是两件互补的事，不能只做一件。
- **长文档只渲「刚改过的那几页」：先用 pdftotext 按关键词定位页码，再 pdftoppm 只渲这几页。** 改了 3 处就只核 3 页，不要一次性渲完 28 页：
  ```bash
  for k in "关注点一" "关注点二"; do
    p=$(pdftotext out.pdf - | awk -v kw="$k" 'BEGIN{p=1} /\f/{p++} index($0,kw){print p; exit}')
    echo "$k -> $p"
  done
  pdftoppm -png -r 100 -f 17 -l 18 out.pdf /tmp/chk   # 只渲这几页
  ```
  `pdftotext` 的换页是 `\f`，在 awk 里先数换页符再匹配关键词就是页码。**只要改了表格（尤其是四列表、或新加了长文本行），就必须回头看图核一遍**——列宽是按文本长度定权的，新增一列长文本会把整表撑变形，而页数可能一点不变。
- **审别人发来的 docx 更严：没渲染过就不要下版式结论。** 抬头用字、有无页码、页码在左还是在右、字体字号、页边距、表格列宽全都读不出来；凭文字或 XML 去「纠正」人家已排好的版式，最常见的后果是把正确的改成错的。内容问题可以直接说，版式问题一律先 `soffice → pdf → pdftoppm → 看图`。

## 5. 内容诚实性：宁可留白，不要编

为一个方向重排内容时，**绝不允许为了填满版面而虚构项目名、客户、规模或角色**。能写的只有：事实底座里已有的经历，以及把已有经历按该方向的语言重述（能力/方法层面的表述）。

事实不够时正确做法：照常出这份版本，用可辩护的能力条目把它做实，然后**给用户一张精确到条目的补充清单**（要哪类项目、资产/交易类型、规模区间、他的角色、结果），说明补上就能做实。不要用「可能参与过」的语气写成既成事实。

**专有名称与法规编号是可核验的，写错就是减分项。** 用户口述的行业术语常与官方名称差一两个字（俗称、旧称、记串）。

**用户特意点明某个字怎么写时，落稿后必须做字形自查。** 机构名、品牌名里的生僻字（用户会补一句「是日字旁的那个 X」）一旦错成形近字，整份文档的可信度就没了。自查三步：`grep -c "<该字>" 源文件` 数出现次数、`grep -o "星.家族" 源文件 | sort -u` 确认没有一处错字，最后抽首页看图核字形没被字体替换成方框（Noto CJK 缺字时会静默缺字而不是报错），交付时把这个自查结果说出来。用户反复强调的事，就是他怕出错的事。凡是要落进正式文档的监管业务名称、资质名、产品名，先查监管文件里的正式表述，**正式名打头、俗称放括号**，例如「风险处置服务信托（不良资产服务信托）」。涉税、合规类经历要点名具体文件号（企业重组特殊性税务处理、资产划转、不良债权以物抵债各有各自的公告号）—— 这类条目是面试官唯一会认真追问的部分，写对了直接建立可信度，写错了当场露馅。

**机构业务线也要外部印证。** 用户说「我在某机构做过某业务」，先确认该机构公开层面确实设有这条业务线（部门名、公开报道、同业是否也有对应部门）。有外部锚点时这条经历在面试里就是可辩护的；找不到锚点时，动词降到「参与／协同」，不要写「主导」。

## 6. 交付形态

### 交付形态按「谁要用它干什么」选，不按「我整理了多少」

把内部资料（台账／清单／模板／SOP）整理成一份厚文档交出去，用户会直接判定「这不像能让人看懂的文件」。整理量是我的工作量，不是他的交付物。同一批素材按用途拆开：

- **要拍板的事 → 一份问卷**：每题一个问句 + 字母选项（`A …｜B …｜C …`）+ **一句「怎么选」的权衡说明**（「想尽快招满选 A；想赚高单价选 B，但招人慢」）+ 每人自填栏（姓名／署名／承担哪几项）+ 交回方式（在线表链接，或群里按 `Q1A / Q2C` 直接回）。控制在一两页、一屏能扫完，选项里带足信息，别让人回来问「A 和 B 差在哪」。
- **要留档的资产 → 单独成件**：把资产（如 SKU 清单、专题库）从母文档切出来做成自足文件，**章节号重编**（母文档里的「五、六」在独立件里改成「一、二」），正文里的「见本稿第 N 节」引用一并改掉或删掉。
- **整理过程物**（SOP、字段模板、逐项回填稿）压到附录或另出一个文件，不要放在开头占掉前几页。
- 交付消息里按「最快能用上的 → 存档件」排序，一件一行，说清怎么用；不要把上一轮的厚文档说成「备查」而不是删掉——留着不碍事，但别让它当主角。

- **docx + PDF 成对给**，同名同目录：docx 是可改件，PDF 是投递件。
- **内容源一起留在交付目录**（复制一份 `_内容源.py` 过去），这样下一轮改一句话就是「改文件 + 跑一行命令」，而不是从零重做。
- 交付时同时报出：改了什么、哪些是新增/重排、哪几处需要用户拍板、哪几处事实缺失。
- **页数超出用户说的量级要如实报，并说明增量来自哪一章。** 用户说「30 来页」而实际 36 页时，写法是「36 页，原来 28 页，新增第五章占 8 页」＋一句「要压到 30 出头我可以砍 X 和 Y，你说」。不要为了让数字好看偷偷删内容——删掉的那段往往正是他这轮要求加的东西。

## 7. 填别人给的表格（应聘登记表／入职登记表／报名表，多为旧版 .doc）

情景与生成文档相反：**版式是别人的**。目标是原格式一字不动、只往格里填字，交付 HR 打开的还是那份 `.doc`。
事实底座从**贴合目标岗位的那一版简历**取（信托岗用财富管理版，别用 AI 版、不良资产版），填表前先把两份简历对齐一遍。

1. `soffice --headless --convert-to docx 表.doc` 转成可编程格式（`.doc` 是二进制，python-docx 读不了）。**表本来就是 `.docx` 时跳过这一步**，直接 `python-docx` 读原文件——不要"先转一份再填"，多一道转换多一次格式漂移。
2. 按**底层 `<w:tc>`** 定位填值：`row.cells` 会把合并格重复吐出来，位置索引和真实 tc 序列不同步，错一格的后果是**默默抹掉一个标签**（例如把「电子邮箱」标签写成邮箱本身）而不是报错。完整定位／写值／加行／勾选代码见 `references/form-fill-legacy-docx.md`。
   **经历段数不够必须加行时，之后所有行号齐平移** —— 所以定位一律走标签（`find_row(t, "业务内容") + 1`、"找 label 右边那一格"），不要先打一遍行号再写死。同名表头出现两次（"家庭主要成员"与"其他近亲属"都有一排 `姓名/与本人关系/…`）取 `[-1]`。
3. 填完 dump 整表文本自检（标签是否被覆盖、勾选是否生效），再渲染看图核对。
4. 交付 `.doc`（`--convert-to doc:"MS Word 97"`）+ `.docx`；原表自带的毛病（中间空白页、页脚「第3页共2页」）不要顺手修，改了就不像原表。

内容边界（签字类文档比版式更容易出事）：

- 只填有依据的字段；推算出来的值（参加工作时间 = 第一份工作入职月）在回复里标明依据。身份证号、婚姻、住址户口、家庭成员、紧急联系人、证明人及联系方式、身高体重血型、薪酬、手签一律留空，回复里给**待补清单**（编号列表，不要表格）。
- **占位符看这份表是交给谁**：直接发 HR 的终稿 → 一格空格都不许有占位符，待补全靠回复里的清单；交给**用户本人继续填的中间稿** → 用 `〔待填〕` + `run.font.highlight_color = WD_COLOR_INDEX.YELLOW`，高亮本身就是"这块要你填"的提示，比清单一对一省事；但交付时必须同时给出高亮清单，并把**签字/日期/家庭成员**单独点出来（这三样只能手写）。用户一次给齐六项之后统一回填并清掉高亮。
- **填完从 2 页涨到 3 页、末页只剩签字行时，先查空单元格。** 原表空着的格子还挂着默认 13pt 的 Calibri 空 run，每行按 13pt 算高，填了字的格子反而是 9pt。修法：全表 run 字号压到 ≤10pt、空段落塞一个 9pt 空 run、每行 `w:trHeight` 改 `atLeast 0`。通常这一轮就掉一页；仍不够就删表单里"奖励情况/处分情况"这类只填"无"的**备用空行**（给 2 行改 1 行，不影响填报）。
- 不发明：高中院校名、出生日期、驾照有无、户口性质没依据就空着。
- 「是否患病／犯罪记录／违纪／处罚／兼职／亲属在目标公司」是**本人签字声明**：按常规勾「无·否」可以，但必须在回复里点名让本人签前自己核一遍。
- 事实底座自相矛盾（两份简历的入职月不一致、本科时间重叠）时，按其中一版填 + 把矛盾摆出来问，绝不静默挑一个版本——背调就查这段。
- 窄格（联系电话／宅电）宁留空，手机填另一格，也别让 11 位号码折成两行。
